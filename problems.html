What Can You Actually Do With INTERCAL?

More than anyone expected. INTERCAL-64 has been used to solve real algorithmic problems — graph traversal, spatial indexing, combinatorial optimization. Along the way, we proved a fundamental result about INTERCAL's control flow that explains why these problems were impossible before.

Knight's Tour (Warnsdorff's Algorithm)

A complete solution to the Knight's Tour on an 8x8 chessboard using Warnsdorff's heuristic with Arnd Roth tiebreaking. Visits all 64 squares. Believed to be the most complex algorithmic implementation in INTERCAL to date.

  • Bitboard representation — the board is a single 64-bit value
  • Precomputed attack masks, clear masks, and center distance tables
  • COME FROM loop with ABSTAIN/REINSTATE control flow
  • ~570 lines across 6 source files
  • Executes in ~30 seconds on modern hardware

Key discovery: The select operator (~) with contiguous high-bit masks implements logical right-shift. INTERCAL has no shift operator, but it doesn't need one.

Hilbert Curve Geographic Indexing

Geographic range queries using Hilbert space-filling curves. Indexes 10 European cities by latitude/longitude, converts to Hilbert indices via Morton code intermediates, sorts, and performs range queries.

Key discovery: INTERCAL's mingle operator ($) IS the standard Morton code algorithm used in production geospatial databases. Bit interleaving is exactly what Morton coding does. This wasn't a port — it was discovering that INTERCAL already had the primitive the geospatial industry independently invented.

DO :1 <- .1 $ .2

Stable Marriage (Gale-Shapley)

The Gale-Shapley stable matching algorithm with n=5. Men propose, women reject, stability emerges. This is the kind of nested-loop, conditional-branch algorithm that INTERCAL was never supposed to handle.

  • COME FROM loops for both inner and outer iterations
  • Double-NEXT trampoline pattern for conditional branching
  • Linearized 25-element preference arrays
  • Dispatch subroutines for indirect indexing

COME FROM Considered Helpful

Formal result: INTERCAL-72 cannot express callable subroutines containing arbitrary-length loops. The maximum loop iteration count is 79, bounded by the NEXT stack depth. COME FROM removes this limitation entirely.

The paper "COME FROM Considered Helpful" proves that the COME FROM statement — widely regarded as INTERCAL's most absurd feature — is computationally necessary for nontrivial programs. The proof uses TLA+ model checking.

Practical consequence: Bubble sort on an array of N elements requires N(N-1)/2 iterations in the worst case. As a callable subroutine in INTERCAL-72, bubble sort is limited to arrays of at most 13 elements: 13 x 12 / 2 = 78 ≤ 79. COME FROM lifts this restriction.

The paper also introduces the double-NEXT trampoline — a pattern for conditional branching inside COME FROM loops that has become the standard technique for all subsequent INTERCAL programs.

Hardware Accelerator

A feasibility study for a dedicated INTERCAL processor with native mingle, select, and unary operations. FPGA prototype estimated at ~$25 BOM. The analysis shows DIVIDE32 would run 7,000x faster in hardware versus the pure-INTERCAL software implementation.

This would be the first hardware implementation of any esoteric programming language.
